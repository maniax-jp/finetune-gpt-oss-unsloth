## 1. エグゼクティブサマリー

現在のファインチューニングは101サンプルのみで実施され、モデルが適切な応答を生成できない状態です。本計画では、信頼できる情報源から体系的にデータを収集し、高品質な300-500サンプルのQAデータセットを構築します。

**成功基準:**
- 最低300サンプル収集（目標500サンプル）
- すべてのデータが検証可能な情報源に基づく
- カテゴリー別にバランスの取れた分布
- 多様な質問パターンと回答スタイル

## 5. 質問パターン設計

### 5.1 質問タイプ分類

| タイプID | タイプ名 | 説明 | 目標割合 | 例 |
|----------|----------|------|----------|-----|
| Q-TYPE-01 | 事実確認型 | 単純な事実を問う | 40% | 「何党ですか？」 |
| Q-TYPE-02 | 詳細説明型 | 詳しい説明を求める | 30% | 「経済政策について教えて」 |
| Q-TYPE-03 | 比較型 | 他者・他時期との比較 | 10% | 「第1次と第2次の違いは？」 |
| Q-TYPE-04 | 時系列型 | 時間的変化を問う | 10% | 「いつから総務大臣？」 |
| Q-TYPE-05 | 背景・理由型 | なぜ・どうしてを問う | 10% | 「なぜその政策を？」 |

### 5.2 質問の文体バリエーション

**丁寧体:**
- 「高市早苗さんは何党ですか？」
- 「高市早苗議員の所属政党を教えてください」

**カジュアル体:**
- 「高市早苗って何党？」
- 「高市早苗さんどこの党？」

**敬語:**
- 「高市早苗先生のご所属政党は？」
- 「高市早苗衆議院議員は何党に所属されていますか？」

**検索的:**
- 「高市早苗 政党」
- 「高市早苗 所属」

### 5.3 回答スタイルガイドライン

**基本原則:**
1. 簡潔で正確な回答
2. 事実のみを記載（憶測・評価を避ける）
3. 必要に応じて補足情報を追加
4. 丁寧な日本語

**回答の長さ:**
- 短答型: 1文（10-30文字）
- 標準型: 2-3文（30-100文字）
- 詳細型: 3-5文（100-200文字）

**例:**

```json
// 短答型
{
  "Q": "高市早苗さんは何党ですか？",
  "A": "自由民主党（自民党）です。"

// 標準型
{
  "Q": "高市早苗さんの現在の役職は？",
  "A": "自由民主党所属の衆議院議員で、現在は自民党政務調査会長を務めています。奈良県第2区選出です。"

# scripts/web_scraper.py
import requests
from bs4 import BeautifulSoup
import json

def scrape_wikipedia_profile(url):
    """Wikipedia infoboxから基本情報を抽出"""
    response = requests.get(url)
    soup = BeautifulSoup(response.content, 'html.parser')

    infobox = soup.find('table', class_='infobox')
    data = {}

    for row in infobox.find_all('tr'):
        header = row.find('th')
        value = row.find('td')
        if header and value:
            data[header.text.strip()] = value.text.strip()

    return data

def convert_to_qa_pairs(data, category):
    """抽出データをQAペアに変換"""
    qa_pairs = []

    # 例: 生年月日
    if '生年月日' in data:
        qa_pairs.append({
            "question": "高市早苗さんの生年月日は？",
            "answer": f"{data['生年月日']}生まれです。",
            "category": category,
            "source": "Wikipedia"
        })

    return qa_pairs
```

**検証ツール:**
```python
# scripts/data_validator.py
import json
from datetime import datetime

class QAValidator:
    def __init__(self):
        self.valid_categories = [f"CAT-{i:02d}" for i in range(1, 11)]
        self.reliability_levels = ["A", "B", "C", "D"]

    def validate_qa_pair(self, qa):
        """QAペアの妥当性を検証"""
        errors = []

        # 必須フィールドチェック
        if not qa.get("question"):
            errors.append("Question is missing")
        if not qa.get("answer"):
            errors.append("Answer is missing")
        if not qa.get("category") in self.valid_categories:
            errors.append(f"Invalid category: {qa.get('category')}")

        # ソース検証
        source = qa.get("source", {})
        if not source.get("url"):
            errors.append("Source URL is missing")
        if source.get("reliability") not in self.reliability_levels:
            errors.append("Invalid reliability level")

        # 文字数チェック
        if len(qa.get("answer", "")) > 500:
            errors.append("Answer is too long (>500 chars)")

        return len(errors) == 0, errors

    def validate_dataset(self, dataset):
        """データセット全体を検証"""
        results = {
            "total": len(dataset),
            "valid": 0,
            "invalid": 0,
            "errors": []
        }

        for idx, qa in enumerate(dataset):
            is_valid, errors = self.validate_qa_pair(qa)
            if is_valid:
                results["valid"] += 1
            else:
                results["invalid"] += 1
                results["errors"].append({
                    "index": idx,
                    "id": qa.get("id"),
                    "errors": errors
                })

        return results
```

| RISK-04 | 著作権問題 | 低 | 高 | 公式・パブリックドメインを優先 |
| RISK-05 | 事実誤認の混入 | 中 | 最高 | 複数ソースでクロスチェック |
| RISK-06 | カテゴリーの偏り | 中 | 中 | 定期的な分布チェック |
| RISK-07 | 収集者のスキル不足 | 低 | 中 | 事前トレーニング実施 |

### 8.2 contingency プラン

**Plan A（推奨）: 順調に進行**
- 2週間で300-500サンプル収集
- 全カテゴリーをバランスよくカバー

**Plan B: 進捗遅延の場合**
- 高優先度カテゴリー（CAT-01, 03, 04）に集中
- 最低200サンプルで第2次トレーニング開始
- 残りは並行して収集継続

**Plan C: 重大な問題発生**
- 既存101サンプルのパラフレーズで200サンプルに拡張
- 簡易的なトレーニングを実施
- 品質改善後に本格収集再開

### B. FAQ

**Q: Wikipedia の情報はどこまで信頼できる？**
A: Wikipedia本文は必ず出典を確認し、出典元の信頼性で判断。出典のない記述は使用不可。

**Q: 古い情報と新しい情報が矛盾する場合は？**
A: より新しい公式情報を優先。矛盾がある場合は両方を記載し、時系列を明記。

**Q: 本人の発言と報道が異なる場合は？**
A: 本人の公式発言を優先。報道は「〜と報じられている」等の表現で区別。
